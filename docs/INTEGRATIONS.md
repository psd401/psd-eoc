# Operational readiness register

<!-- psd-eoc:readiness-register -->

This is the repository's only current source for deployment, DNS, identity,
monitoring, provider, and mobile-distribution readiness. Durable runbooks link
here instead of copying time-sensitive claims. Update an entry only from dated,
retained evidence; do not infer live state from source code or synthesis.

Allowed labels:

- `mocked`: synthetic, fail-closed behavior only;
- `configured-unverified`: configuration or a partial provider boundary is
  proved, but the complete path is not;
- `live-verified`: the stated boundary was observed live on the evidence date;
- `blocked`: a required boundary is unavailable or deliberately disabled.

Last consolidated from retained evidence: **2026-09-08**.

Client-observed failures are reported to `POST /api/diagnostics` and logged as
`client-diagnostic`. This exists because nothing the server logs can explain a
request it never received: an emergency drill ran with the phone reporting an
unavailable timeline while the server recorded nothing at all. The reporter
shipped inert in 1.0.9 -- the client was constructed without it -- and is
connected from 1.0.10, so no client diagnostic before that build exists.

Remote updates are disabled for the current embedded-only runtime. This is an enforced architectural boundary, not a configuration default: push registration derives `updateMode` from the disabled-updates constants in `packages/mobile/src/lib/push/native-port.ts`, `NativePushBuildIdentitySchema` accepts only the `embedded-only` literal, and the `device_push_token_registrations_embedded_only` CHECK constraint rejects any other value. Enabling remote updates without first changing the contract, adding a superseding migration, and reworking the update diagnostic would stop all push registration.
